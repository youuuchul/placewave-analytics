# 대시보드 화면 값 vs BigQuery 재집계 대조

가상 서비스 시나리오로 생성한 데이터 · 실제 서비스 데이터 아님.

결론: 대조 16개 항목 모두 일치(불일치 0). 같은 이름으로 보이던 값 두 쌍(신청 11,347 vs 11,348, 취소율 9.5% vs 7.4%)은 날짜 귀속·분자 기준이 다른 정의 차이로 확인했고, 화면 라벨과 파이프라인 검사로 정리했다.

- 기준일 2026-09-20(`meta.to_date`), 데이터 2026-09-23 추출(`source = bigquery`)
- 화면 값: `npm run build` 후 vite preview 를 띄우고 Playwright(Chromium, 1440×900)로 타일 값·보조 문구를 읽음. 지연 표 로딩이 끝난 뒤(`[data-pending]` 없음) 읽음
- 재집계: 마트가 아니라 `staging.int_person_day`·`staging.fct_order`·`staging.dim_contract`·`staging.dim_subscription`·`raw.db_venues` 에서 직접 `COUNT(DISTINCT person_id)` 등으로 셈. 개인 GCP `scripts/bq.sh query`, SELECT만
- 기간: 28일 = 2026-08-24 ~ 09-20, 90일 = 06-23 ~ 09-20, 1년 = 2025-09-22 ~ 2026-09-20(데이터 시작일로 잘려 364일)
- 금액 타일은 `억`·`만` 단위로 반올림해 보이므로, 재집계 원 단위 값을 같은 규칙으로 줄여 비교함

## 2. 같은 이름, 다른 값 — 원인과 처리

### 신청 11,347(흐름·개요) vs 11,348(행사별), 결제 6,446 vs 6,447

- 원인: 날짜 귀속이 다름. `daily_metrics` 는 `int_person_day` 를 거쳐 행동을 **세션 시작일**에 붙이고, `daily_event` 는 원장의 **신청일**을 씀. 8/23에 시작해 자정을 넘겨 8/24에 신청·결제한 세션 1건(신청 1·결제 1)이 흐름 보기에서는 8/23(기간 밖), 행사별 보기에서는 8/24(기간 안)에 들어감
- 규모: 전 기간 신청 77,786건 중 396건(0.5%)이 세션 시작일과 다른 날 신청. 기간 끝(9/20)은 다음 날 데이터가 없어 경계 차이가 한쪽(시작일)에서만 생김
- 전 기간 합은 같음: 신청 77,786 = 77,786, 결제 금액 1,668,876,800 = 1,668,876,800
- 결제 금액 28일도 로그(세션 시작일) 225,057,350 vs 원장(결제일) 225,082,350 로 1건(25,000원) 차이 — 같은 원인
- 처리: 두 보기의 기준을 한 원천으로 합치지 않음. 흐름 보기는 사람·세그먼트 축이 필요해 로그 계열(`person_day` 와 같은 세션 시작일)이어야 하고, 행사별 보기는 행사 축이 필요해 원장이어야 함. 정의를 `docs/dashboard.md` §3 `날짜 귀속` 행에 적고, 파이프라인 검사에 `C12a`(신청 전 기간 합)·`C12b`(결제 금액 전 기간 합)·`R9`(세션 시작일과 다른 날 신청 비중, 0~2%)를 추가

### 취소율 9.5%(흐름) vs 7.4%(행사별)

- 원인: 분자 기준이 다름. 흐름 보기의 `daily_metrics.cancels` 는 **취소일** 기준 로그라 기간 이전에 신청한 건의 취소도 들어감. 행사별 보기의 `daily_event.cancels` 는 **그날 신청분 중 취소된 건**(신청일 코호트)이라 기간 막바지 신청분은 아직 취소될 시간이 없음
- 28일 재집계: 취소일 기준 1,082건 = 로그 1,082건, 신청일 기준 839건
- 처리: 행사별 보기·월간 탭(`monthly_summary` 도 신청일 기준 원장)의 타일·열 이름을 `신청분 취소율`로 바꾸고 지표 가이드에 C21 을 새로 둠. 흐름 보기 C06 정의에 취소일 기준을 명시

## 4. 한계

- 화면 값은 반올림 표시(억·만·%)라 원 단위 일치는 재집계 값을 같은 규칙으로 줄여 확인함. 원 단위 대조는 검사 C1b·C9·C12b 가 맡음
- 회원 필터·회원 분해는 사람마다 기간 안 마지막 방문일의 회원 여부로 귀속(`persons.ts` `'last'`). 이 데이터에서는 회원이 비회원으로 돌아가는 경우가 없어 "회원인 날이 하루라도 있음" 규칙과 결과가 같음
- 1년 프리셋은 데이터 시작일에 잘려 364일이며, 직전 기간이 데이터 밖이라 증감을 표시하지 않음
